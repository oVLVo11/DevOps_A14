课程阿里云服务器访问容器内的`deb.debian.org`连续两次停在软件包索引下载，宿主机对阿里云 Debian 镜像访问正常。Dockerfile 因此将 Debian 主源和安全源切换为`https://mirrors.aliyun.com`，apt 仍校验仓库签名；基础 Python 镜像的固定 OCI digest 未改变。

课程镜像内直接执行`pytest`时，控制台入口没有把`/app`加入模块搜索路径，导致已复制到镜像的`/app/buildchecker`无法导入。`make test`改为`python3 -m pytest`，明确用当前工作目录启动同一固定版本的pytest；服务器诊断命令已验证三项测试通过。

## 服务器证据

服务器证据必须由课程分配的 Ubuntu 主机真实运行后填写，不能用 Windows 静态检查或 E3 的 WSL 日志替代。正式交付应选择两份独立克隆的成功运行目录，记录：

- 服务器环境与 Docker 版本；
- 被测源码完整 SHA；
- 两名操作者或两份独立学号目录；
- `env.json`、`build.log`、`image.json`、`toolchain.lock`；
- `test.log`、`smoke.json`、`secret-scan.txt`；
- 假 Key 检出与清理后复扫记录；
- 两次结果的对照与合理差异。

镜像 ID、时间、进程号和 `trace_lines` 可能不同；源码 SHA、工具链版本、测试结论与冒烟结论应一致。
