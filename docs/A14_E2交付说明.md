## 4. A14 接口

### FULL_CHECK

端点：`POST /v1/full-check-jobs`。

输入绑定固定仓库 URL、40 位 commit、clean build 命令、工作目录，以及 DRAFT 产生的 `image_ref`、`configuration_id`、`dockerfile_uri`、`producer_job_id`。

成功输出：

- `actual_graph_uri`；
- `declared_graph_uri`；
- `error_report_uri`；
- 对应 Artifact 元数据。

发现 MD/RD 是正常结果，Job 状态仍为 `SUCCEEDED`。只有分析器、执行器或环境异常才使用失败状态。

### INCREMENTAL_CHECK

端点：`POST /v1/incremental-check-jobs`。

除 FULL_CHECK 公共输入外，必须包含：

- 当前 commit；
- `base_commit`；
- 与 base commit、同一仓库、同一 `configuration_id` 绑定的 baseline actual graph 与报告。

成功输出更新后的 actual/declared graph、报告和 `findings_delta.added/removed`。配置变化时不得复用旧 baseline。

## 5. 向 MDFixer 交接

完整检测报告可以同时包含 MISSING 和 REDUNDANT。REPAIR 只接受非空 MD-only 报告。A14 从完整报告过滤 REDUNDANT 时保留 `finding_id`、repository、commit、configuration、producer 和证据字段，不静默修改发现的身份。

MDFixer 候选 patch 返回后，A14 在相同基线、相同环境和候选工作树上重检。重检报告必须绑定 `patch_uri`；B14 只有在 build、verify、recheck 均通过且 `remaining_missing=0` 时才能接受候选。

## 6. 验收与限制

本包证明：协议对象可校验、人工产物可读取、SHA-256 一致、跨字段绑定有效、典型非法输入会被拒绝。

本包不证明：真实 HTTP 服务可用、真实镜像可拉取、ptrace 能在容器内运行、算法复现正确、真实项目构建成功或双方已完成 E3 联调。
