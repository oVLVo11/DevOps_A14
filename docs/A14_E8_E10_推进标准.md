# A14 E8–E10 推进标准

本标准接续本仓库已完成的 E7 BuildChecker 成果。A14 的第二篇论文是 EChecker（ISSTA 2024）；BuildChecker（TSE）用于建立真实全量基线及交叉核对。所有结论应区分论文原方法、受限教学实现与 A14 自己运行的证据。

## 1. 导入与保护既有成果

在 A14 原仓库的独立分支导入 `labs/e8e10/`、`run_lab.py` 和 `.github/workflows/e8e10.yml`，通过 PR 合入 `main`。保留 E7 源码、`e7-quality-gate.yml` 及既有必需检查。导入前后核对源文件差异、分支、提交 SHA、两项检查和 PR 产物；每名成员随后同步 `main` 并在个人分支工作。`work/` 只保存原始运行证据，不随源码提交。课堂分发包的 B 轨道参考代码属于统一教学包，A14 不据此声称完成 B14 工作。

完成判定：导入 PR 已合并，A14 的 `main` 包含三个新增路径，原 E7 检查继续生效，新增 `e8e10-quality-gate` 成功；记录合并 SHA 和运行 URL。若远程检查尚未完成，记录实际状态，不以本地测试代替。

## 2. E8：历史图基线

在固定 C0 输入上运行真实 BuildChecker，保存 trace、Make 数据库、实际图、声明图与发现；将对象目标的实际图投影为 EChecker 历史图。对未变化 C0 再扫描，核对 `main.o` 缺 `config.h`、冗余 `unused.h`，以及两个目标复用、零刷新。保存 `baseline.json`、`buildchecker/`、`incremental.json`、源码与镜像身份。

## 3. E9：逐提交更新

沿 C0→C1→C2→C3 的真实 Git 历史运行：普通函数体变化复用；新增 include 刷新并新增 `extra.h` 的 MD；补齐 Make 声明后消除两项 MD，保留 `unused.h` 的 RD。分别保存真实 `make` 日志和每次的 `actual`、`declared`、`findings`、`added`、`resolved`、`reused`、`refreshed`。每人增加至少一个有独立预期的测试或实现改动。

## 4. E10：一致性、计时与质量判定

对 unchanged、body、include、declaration、flags、header 六类变化各重复五次；逐次比较增量与全量的完整实际图、声明图和发现集合，保留 30 行原始 CSV 与每次 JSON。按场景报告本机耗时中位数，并写清计时只覆盖教学扫描路径。最终运行 BuildChecker 全量动态重检，保存原始 trace 和报告。只有全部预期通过才标记质量门禁通过。

## 交付与论文边界

个人报告、ADR、AI 使用记录须写明外层源码 SHA、样例项目提交、镜像 ID、命令、原始输出、独立预期、个人代码贡献及未完成项。PR 应绑定最新 `headSha` 和 Actions 产物，同时保留 E7 必需检查。

教学 `scan` 只覆盖固定 C/Make 样例，用 `gcc -MM` 与保守签名失效更新对象目标依赖；它尚未实现 EChecker 论文中的增量系统调用图归并、按受影响目标更新、复杂规则及文件增删改名处理。BuildChecker 的全量动态重检是交叉核对；EChecker 论文中的性能比较对象为 Buildfs。课堂数据和论文的 12 项目、240 提交结果分别报告，不能混用。

依据：`论文/_ISSTA_2024__Detecting_Build_Dependency_Error.pdf` §3、§5；`论文/_TSE__BuildChecker.pdf` §4；课程包 A 组 E8/E9/E10 手册与个人报告模板；本仓库 E7 验收记录。
