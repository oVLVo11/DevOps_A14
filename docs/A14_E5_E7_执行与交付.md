# A14 E5–E7 执行与交付

本说明接续本仓库已完成的 E4，不重新初始化 Git 仓库，不重新添加远程，也不复制 B 组服务。A14 的远程仓库是 `https://github.com/oVLVo11/DevOps_A14.git`。所有需要 Docker、strace 的证据在本组课程 Linux 服务器上由本组代码重新生成。`work/` 被 Git 忽略，运行后应单独备份完整证据目录。

## 代码对应的任务

|阶段|本仓库实现|验收证据|
|---|---|---|
|E5|独立副本 clean build，`strace -ff` 记录文件和进程系统调用，`make -p` 保存声明数据库；核对实际 `config.h` 打开和 `main.o` 声明|原始 `trace/t.*`、`make-db.txt`、输入副本、程序输出、校验日志|
|E6|`full-check` 从真实构建归属编译进程，建立实际图和声明图，报告 MD/RD；仅在独立副本中修改 Makefile 后复检|修复前后 `findings.json`、两类图、进程图、原始 trace、构建日志、输入 SHA-256|
|E7|容器内服务测试、三次原始故障、修复样例、构建失败、多输出和超时；独立判定测试及 GitHub 工作流|`gate-result.json`、`results.csv`、各场景日志、正常/失败/恢复 CI 和分支保护记录|

附加的服务测试 `test_full_check_findings_are_successful_analysis_but_fail_optional_gate` 验证：检测到 MD/RD 时分析本身仍是 `SUCCEEDED`，只有显式启用 `--fail-on-findings` 的质量门禁才返回非零。这与 E2 的 `FULL_CHECK` 结果语义一致。基础教学包为 15 项服务测试；本仓库新增后为 16 项，故意失败演示添加测试后为 17 项，其中 1 项预期失败，修复后 17 项通过。独立判定测试另有 6 项。


运行 ID 必须唯一。脚本要求干净工作区和仓库级数字学号，顺序执行环境自检、镜像构建与测试、E5 取证、E6 缺陷和修复复检、6 项独立判定测试、E7 八项完整门禁及密钥扫描。E6 修复前预期退出码为 `1`，但报告状态必须为 `SUCCEEDED` 且精确报告两项依赖错误；脚本会显式核对这个预期。失败时保留已有日志并停止，修好环境后更换运行 ID 重跑。

## GitHub CI 与真实合并门禁

仓库已经包含 `.github/workflows/e7-quality-gate.yml`、`ci/A-main-protection.json` 和故意失败/修正测试。先确保正常提交的 `e7-a-quality-gate` 成功，再读取该检查实际 `app_id`，与保护配置中的 `15368` 核对；如不同，更新 JSON 后才设置保护。以下命令在已登录 `gh` 的服务器上执行，`repo` 从当前仓库获取，不创建新仓库：

```bash
repo=$(gh repo view --json nameWithOwner --jq .nameWithOwner)
sha=$(git rev-parse HEAD)
gh run list --limit 5
gh api "repos/$repo/commits/$sha/check-runs" --jq '.check_runs[] | {name, conclusion, app_id: .app.id, app_slug: .app.slug}'
gh api --method PUT "repos/$repo/branches/main/protection" --input ci/A-main-protection.json
gh api "repos/$repo/branches/main/protection" > work/main-protection.json
```

随后在单独演示分支提交故意错误测试，发起 PR，等待检查失败，实际尝试合并并保留拒绝日志；再将测试修正为正确预期，等待**最新提交**的检查成功并合并。演示只改变测试预期，算法源码保持不动。可按以下路径复制模板：

```bash
git switch -c e7-gate-reject-demo
cp ci/rejection-demo/A/test_ci_reject_demo.py services/buildchecker/tests/
git add services/buildchecker/tests/test_ci_reject_demo.py
git commit -m "Demonstrate E7 CI rejection"
git push -u origin e7-gate-reject-demo
gh pr create --base main --head e7-gate-reject-demo --title "Demonstrate E7 merge rejection" --body "验证故意错误测试被 CI 与 main 保护拦截，随后修正测试。"
pr_num=$(gh pr view e7-gate-reject-demo --json number --jq .number)
```

记下 PR 编号和失败 run ID。故意失败场景中的检查命令返回非零是预期现象，仍要保存原始输出和退出码：

```bash
mkdir -p work/ci-rejection
if gh pr checks "$pr_num" --watch > work/ci-rejection/checks.log 2>&1; then check_code=0; else check_code=$?; fi
printf '%s\n' "$check_code" > work/ci-rejection/checks.exit-code.txt
fail_run=$(gh run list --branch e7-gate-reject-demo --event pull_request --limit 1 --json databaseId --jq '.[0].databaseId')
gh run view "$fail_run" --log-failed > work/ci-rejection/failed-check.log
gh run download "$fail_run" --dir "work/ci-rejection/artifacts-$fail_run"
if gh pr merge "$pr_num" --merge > work/ci-rejection/merge-rejection.log 2>&1; then merge_code=0; else merge_code=$?; fi
printf '%s\n' "$merge_code" > work/ci-rejection/merge.exit-code.txt
gh pr view "$pr_num" --json state,mergeStateStatus,headRefOid,url > work/ci-rejection/PR.json
gh api "repos/$repo/branches/main/protection" > work/ci-rejection/protection.json
```

检查 `check_code` 与 `merge_code` 都非零，PR 仍为 `OPEN`，并核对 `mergeStateStatus` 与拒绝消息；只有确实观察到拒绝，验收项才能记 PASS。

```bash
cp ci/rejection-demo/A/fixed/test_ci_reject_demo.py services/buildchecker/tests/
git add services/buildchecker/tests/test_ci_reject_demo.py
git commit -m "Correct E7 success oracle"
git push
gh pr checks "$pr_num" --watch
mkdir -p work/ci-recovery
pass_run=$(gh run list --branch e7-gate-reject-demo --event pull_request --limit 1 --json databaseId --jq '.[0].databaseId')
gh run download "$pass_run" --dir "work/ci-recovery/artifacts-$pass_run"
gh pr view "$pr_num" --json state,mergeStateStatus,headRefOid,url > work/ci-recovery/PR-before-merge.json
gh pr merge "$pr_num" --merge
gh pr view "$pr_num" --json state,mergedAt,mergeCommit,url > work/ci-recovery/PR-merged.json
```

保存正常、失败、恢复三次 run URL、提交 SHA 和 artifact，下载 artifact 到 `work/ci-*` 备份。最终填写 [实验报告](A14_E5_E7_实验报告.md)和[验收记录](A14_E5_E7_验收记录.csv)，现场可从报告中的 trace 行、`trace_id` 和 CI URL 回到原始证据。不要把教学包自带的助教运行记录、Windows 本地测试或尚未运行的 CI 写成本组完成记录。

## 能力边界

当前检测器支持单个 GNU Make 进程及每个 recipe 任务一个最终输出。成功的只读打开作为实际依赖的近似观测；复杂 Make 宏、递归 Make、动态 FD 路径、符号链接和多输出任务会显式失败或不在本次精度保证内。`REDUNDANT` 的意思是本次构建配置下未观察到读取，不是所有配置都永远无用。EChecker 增量算法、E2 HTTP 作业接口与 B14 真实服务联调仍需后续阶段实现。
